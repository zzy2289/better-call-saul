# E-commerce Refunds

## Common dispute types

- Item not received.
- Item arrived damaged.
- Item not as described.
- Used/open-box item sold as new.
- Counterfeit or suspicious authenticity.
- Missing parts.
- Wrong item.
- Delayed shipment that missed a promised date.
- Seller refuses return or refund.
- Platform closes dispute too early.

## Core question

Is this a change-of-mind return, or did the seller/platform fail to deliver what was promised?

The second category is usually stronger.

## Evidence checklist

- Order page screenshot.
- Product listing screenshot.
- Seller claims or chat messages.
- Delivery tracking.
- Photos/video of packaging and item.
- Serial number or condition evidence.
- Return request date.
- Support ticket numbers.
- Platform policy links if available.

## Strong angles

### Not as described

Use when listing promises differ from item received.

Frame:

```text
This is not a preference return. The item delivered does not match the listing representation.
```

### Defective on arrival

Use when item was unusable or damaged at delivery.

Frame:

```text
The defect was present on arrival, documented immediately, and prevents normal use.
```

### Missed promised delivery date

Use when delivery timing was material.

Frame:

```text
The delivery date was part of the purchase decision, and the delay defeated the purpose of the order.
```

### Seller delay caused return-window issue

Use when user contacted within time but support dragged it out.

Frame:

```text
The issue was reported within the relevant period. The delay came from the resolution process, not from my inaction.
```

## Refund request template

```text
Hi, I am requesting a refund for order [order number].

This is not a change-of-mind return. The item does not match the listing because [specific mismatch]. I have attached [evidence].

I am requesting [refund/replacement/return label] by [date]. If this cannot be handled by this support queue, please escalate it to the marketplace dispute or buyer protection team.
```

## Chargeback caution

A payment-provider dispute can be legitimate when the user paid for goods/services that were not delivered as promised and the merchant/platform will not resolve it.

Do not recommend chargebacks for buyer's remorse, false claims, or attempts to keep goods without a legitimate basis.

## Saul angle

The best e-commerce case usually sounds less like "I am mad" and more like "the transaction delivered something materially different from what I paid for."
